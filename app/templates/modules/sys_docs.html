1 · Visión general

El panel de Contenedores / Sistema permite ver el estado de todos los servicios del stack WardNode y reiniciarlos de forma individual, sin necesidad de acceso SSH al servidor.

El control se realiza mediante el Docker SDK desde la consola Flask. La consola tiene acceso al socket Docker del host (bind-montado en la imagen) y puede inspeccionar y controlar los contenedores del stack.

Este panel está orientado a operaciones de mantenimiento rutinario: recargar configuración tras cambios en Nginx, reiniciar un contenedor que haya fallado, o comprobar el estado del stack antes de un despliegue.

3 · Reinicio seguro

El reinicio es por contenedor individual — no hay opción de reiniciar el stack completo desde este panel. Esto es deliberado: reiniciar todos los contenedores a la vez podría interrumpir el tráfico y causar una interrupción de servicio.

No reiniciar la consola WardNode (wardnode-console) desde este panel. Reiniciar la consola mientras hay una sesión activa cierra la sesión inmediatamente y puede interrumpir operaciones en curso (regeneración de configs, ingesta de eventos WAF, etc.).

Para reiniciar la consola, usar docker compose restart wardnode-console desde el host con acceso SSH.

Cuándo reiniciar el proxy

Reiniciar wardnode-proxy desde este panel equivale a docker compose restart proxy. Es necesario en los siguientes casos:

  • Tras cambios manuales en archivos de configuración Nginx (fuera del ciclo normal de regeneración de la consola).
  • Si el proxy queda en estado restarting o no responde.
  • Tras actualizar la imagen del proxy (el reinicio aplica la nueva imagen si ya fue descargada).

La consola regenera y recarga Nginx automáticamente tras guardar configuración — este botón es solo para casos excepcionales.

{# ── 4. Diagnóstico y estado ─────────────────────────────────── #}

4 · Diagnóstico y estado

El panel muestra el estado de cada contenedor en tiempo real:

EstadoSignificadoAcción recomendada
running El contenedor está activo y respondiendo. Ninguna.
stopped / exited El contenedor se ha detenido, ya sea de forma planificada o inesperada. Revisar logs. Si es inesperado, reiniciar desde este panel o investigar la causa.
restarting Docker está intentando reiniciar el contenedor repetidamente (crash loop). Revisar logs con docker logs <nombre> desde el host para identificar el error de arranque.

Si un contenedor aparece como stopped inesperadamente, las fuentes de información para el diagnóstico son:

  • Grafana/Loki (si OBS está activo): revisar el dashboard NGINX Logs (04) para logs del proxy.
  • SSH al host: docker logs wardnode-<nombre> para el log completo del contenedor.
  • Audit Log de WardNode (/audit/): muestra acciones recientes del sistema que puedan haber causado el problema.
