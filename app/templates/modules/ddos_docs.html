1 · Visión general

WardNode CrowdSec detecta y bloquea ataques de SSH brute-force y otros patrones maliciosos en la red del servidor host. El módulo integra CrowdSec directamente en la consola WardNode, permitiendo gestionar decisiones, bans manuales y whitelist desde el navegador.

El stack CrowdSec se compone de dos contenedores que trabajan juntos:

ContenedorFunción
wardnode-crowdsec Motor IDS. Analiza logs del sistema (SSH, Nginx, etc.) y genera "decisiones" de ban de IPs cuando detecta comportamiento anómalo.
wardnode-crowdsec-bouncer Aplica las decisiones CrowdSec directamente en nftables del kernel. Las reglas se crean a nivel de red antes de que cualquier proceso del host las vea.

Requiere que el módulo WF (WardNode WF) esté instalado y activo, ya que WF gestiona la infraestructura de red del host sobre la que CrowdSec opera.

{# ── 2. Arquitectura ─────────────────────────────────────────── #}

2 · Arquitectura

El control de CrowdSec se realiza vía Docker SDK (no vía socket WF), gestionando directamente los contenedores CrowdSec:

Consola Flask (contenedor)
      │  Docker SDK
      ▼
wardnode-crowdsec (motor IDS)
      │  decisiones (JSON)
      ▼
wardnode-crowdsec-bouncer
      │  nftables
      ▼
Kernel del host (bloqueo de IPs)

Los módulos relevantes en la consola son:

MóduloResponsabilidad
app/ddos/control.pyOperaciones start/stop/ban/unban vía Docker SDK y cscli.
app/ddos/ingest.pyIngesta de decisiones CrowdSec activas.
app/ddos/safety.pyGestión de safe-IPs (whitelist) — IPs que nunca se banean.

El bouncer actúa vía nftables (no UFW) — las reglas se crean directamente en el subsistema de red del kernel, con mayor prioridad que las reglas UFW.

{# ── 3. Requisito: módulo WF ─────────────────────────────────── #}

3 · Requisito: módulo WF activo

WardNode WF debe estar instalado y activo antes de activar el módulo CrowdSec. El script de instalación del agente WF (host-agent/install.sh) instala también CrowdSec en el host (desactivado por defecto).

Si el módulo WF se desactiva posteriormente, CrowdSec queda sin la infraestructura de red gestionada y las decisiones de ban pueden no aplicarse correctamente.

Para activar WardNode CrowdSec por primera vez:

  1. Instalar y activar el módulo WF.
  2. Completar la inicialización del firewall (paso obligatorio en WF).
  3. Activar el módulo CrowdSec desde este panel.
{# ── 4. Decisiones y bans activos ────────────────────────────── #}

4 · Decisiones y bans activos

El panel principal de CrowdSec muestra la lista de decisiones activas generadas por el motor. Para cada decisión se muestra:

CampoDescripción
IPDirección IP baneada (puede ser IPv4 o IPv6).
DuraciónTiempo restante del ban.
RazónMotivo del ban (ej. crowdsecurity/ssh-bf para SSH brute-force).
OrigenFuente de la decisión: cscli (manual), crowdsec (automático), crowdsecurity/CrowdSec (comunidad).

Las decisiones se generan automáticamente por el motor CrowdSec al detectar comportamiento anómalo en los logs del sistema. Un ban automático no requiere intervención del operador.

{# ── 5. Ban / Unban manual ───────────────────────────────────── #}

5 · Ban / Unban manual

Además de los bans automáticos, el panel permite gestionar bans de forma manual:

Banear una IP

  • IP: dirección IPv4 o IPv6 a banear.
  • Duración: en formato CrowdSec — 30s, 5m, 1h, 7d, 1M.
  • Razón: solo letras, números, guiones y guiones bajos (la validación se aplica en servidor). Ejemplo: manual-ban, suspicious_scan.

Desbanear una IP

Desde la lista de decisiones activas, usar el botón de desbanear para eliminar la decisión inmediatamente. El bouncer retira la regla nftables en segundos.

{# ── 6. Safe-IPs / Whitelist ─────────────────────────────────── #}

6 · Safe-IPs / Whitelist

Las IPs en la whitelist (Safe-IPs) nunca son baneadas por CrowdSec, independientemente de su comportamiento. Las IPs se normalizan a forma canónica antes de guardarse (ejemplo: ::ffff:1.2.3.4 → 1.2.3.4).

Recomendación: añadir la IP de tu oficina, VPN o cualquier fuente de tráfico legítimo intenso a la whitelist antes de activar CrowdSec. Sin esta precaución, los patrones de acceso normales de un administrador (múltiples conexiones SSH, scrips de despliegue, etc.) pueden desencadenar un ban automático.

La gestión de Safe-IPs está disponible en el panel CrowdSec → sección "Safe-IPs". Se pueden añadir y eliminar IPs individualmente.

{# ── 7. Activar / Desactivar ─────────────────────────────────── #}

7 · Activar / Desactivar

AcciónEfecto
Activar Levanta los contenedores wardnode-crowdsec y wardnode-crowdsec-bouncer. CrowdSec empieza a analizar logs y aplicar decisiones inmediatamente.
Desactivar Detiene ambos contenedores. La protección CrowdSec queda inactiva. Las reglas nftables activas son retiradas por el bouncer al detenerse.

Al reactivar, CrowdSec retoma el análisis desde donde lo dejó — los logs acumulados mientras estuvo inactivo no se procesan retroactivamente, pero el historial de decisiones previas sigue disponible.
