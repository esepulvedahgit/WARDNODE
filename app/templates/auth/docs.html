1 · Visión general

WardNode usa un sistema de roles con tres niveles de acceso que permite ajustar los permisos de cada operador según su responsabilidad. Los usuarios se gestionan desde el panel de administración y cada uno gestiona su propia seguridad de cuenta desde el perfil.

La autenticación de dos factores (TOTP) es opcional pero recomendada para todas las cuentas, especialmente las de tipo admin. El secreto TOTP se almacena cifrado y requiere WARDNODE_SECRET_KEY para funcionar.

{# ── 2. Roles y permisos ─────────────────────────────────────── #}

2 · Roles y permisos

RolAccesoLimitaciones
admin Acceso completo: crear/eliminar usuarios, todos los módulos, ajustes, restaurar backups Sin limitaciones
operator Gestión del proxy/WAF y módulos activos (WF, OBS) Sin acceso a: usuarios, ajustes, backup, auditoría, SOC config
reader Solo lectura: dashboard, eventos, logs, SOC (vista), OBS No puede modificar ninguna configuración
El sistema requiere siempre al menos un usuario con rol admin. No es posible eliminar el último administrador ni cambiar su rol a uno inferior.
{# ── 3. Gestión de usuarios ──────────────────────────────────── #}

3 · Gestión de usuarios (solo admin)

La gestión de usuarios está disponible para administradores en Admin → Usuarios.

Crear usuario

Desde el formulario "Nuevo usuario": introduce nombre, email, rol y contraseña inicial. El usuario podrá cambiar su contraseña desde su perfil en cualquier momento.

Eliminar usuario

Botón de eliminar en la lista de usuarios. Restricciones:

  • No se puede eliminar el propio usuario activo (sesión actual).
  • No se puede eliminar el último usuario con rol admin.

Política de contraseñas

Mínimo 8 caracteres. La contraseña debe incluir letras y números. No se permite una contraseña compuesta solo de letras o solo de números.

{# ── 4. MFA / TOTP — Enrolamiento ────────────────────────────── #}

4 · MFA / TOTP — Enrolamiento

Cada usuario gestiona su propio TOTP desde Mi perfil → sección "Autenticación de dos factores".

Pasos de enrolamiento

  1. Clic en "Configurar 2FA" → WardNode genera un código QR con el secreto TOTP.
  2. Escanear el código QR con una app autenticadora compatible (Google Authenticator, Authy, 1Password, Bitwarden, etc.).
  3. Introducir un código válido de 6 dígitos generado por la app para confirmar el enrolamiento.
El secreto TOTP se almacena cifrado en la base de datos (totp_secret en la tabla user) y requiere WARDNODE_SECRET_KEY. Si la clave cambia, los secretos TOTP existentes quedarán ilegibles.
{# ── 5. Flujo de login con TOTP activo ───────────────────────── #}

5 · Flujo de login con TOTP activo

Cuando un usuario tiene TOTP activo, el login se realiza en dos pasos:

  1. Paso 1: Introducir email y contraseña. Si son correctos, el sistema pide el código TOTP.
  2. Paso 2: Introducir el código de 6 dígitos de la app autenticadora. El código es válido durante 30 segundos (ventana de una ranura anterior/posterior para tolerar pequeños desfases de reloj).
Si el dispositivo TOTP se pierde: un administrador puede desactivar el TOTP del usuario afectado desde la gestión de usuarios en la consola, permitiéndole volver a hacer login solo con contraseña y configurar un nuevo dispositivo.
{# ── 6. Desactivar MFA ───────────────────────────────────────── #}

6 · Desactivar MFA

Para desactivar el TOTP del propio usuario:

  1. Ir a Mi perfil → sección "Autenticación de dos factores".
  2. Clic en "Desactivar 2FA".
  3. Confirmar la contraseña actual para verificar la identidad.

Un administrador también puede desactivar el TOTP de cualquier usuario desde Admin → Usuarios, sin necesidad de conocer la contraseña del usuario afectado.

{# ── 7. Reset de contraseña por email ────────────────────────── #}

7 · Reset de contraseña por email

WardNode incluye un flujo de reset de contraseña por email para casos en que el usuario no recuerda su contraseña actual:

  1. En la pantalla de login: enlace "¿Olvidaste tu contraseña?".
  2. Introducir el email de la cuenta → se envía un enlace de reset al email registrado.
  3. El enlace es válido durante PASSWORD_RESET_TOKEN_MINUTES minutos (default: 30).
  4. Al hacer clic en el enlace: introducir y confirmar la nueva contraseña.
Requisito: SMTP debe estar configurado en Ajustes para que el envío del email funcione. Sin SMTP configurado, esta funcionalidad no está disponible.
