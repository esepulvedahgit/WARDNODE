1 · Visión general

WardNode registra automáticamente todas las acciones significativas realizadas por los operadores y los eventos internos del sistema. Este registro es la trazabilidad completa de quién hizo qué y cuándo.

  • El log de auditoría es inmutable desde la UI — no se puede editar ni eliminar ninguna entrada a través de la interfaz de WardNode.
  • Solo los administradores pueden acceder al log de auditoría (/audit/).
  • Cada entrada se escribe con un SAVEPOINT de SQLAlchemy, de modo que nunca interfiere con la transacción del operador que la generó — si la acción principal falla, el registro de auditoría se guarda igualmente.

3 · Campos del evento de auditoría

CampoTipoDescripción
actor_email string Email del usuario que realizó la acción (o "system" para eventos automáticos)
action string Identificador de la acción (ej: proxy.site.create, auth.login.success)
resource_type string Tipo del recurso afectado (ej: site, user, rule)
resource_name string Nombre o ID del recurso afectado
severity enum info (operación normal), warning (acción notable), error (fallo), critical (acción de alto impacto)
status enum success o failure
detail JSON Información adicional específica de la acción (IPs, cambios de configuración, etc.)
timestamp datetime Fecha y hora UTC del evento
{# ── 4. Filtros y visualización ──────────────────────────────── #}

4 · Filtros y visualización

El dashboard de auditoría (Auditoría) ofrece varias herramientas para explorar el log:

  • Filtro por severidad: mostrar solo eventos de un nivel determinado (info, warning, error, critical).
  • Filtro por recurso: limitar la vista a un tipo de recurso específico (site, user, rule, etc.).
  • Filtro por actor: ver únicamente las acciones de un operador concreto.
  • Filtro por rango de fechas: acotar el período de tiempo a analizar.
  • Timeline: gráfico de eventos por hora que muestra picos de actividad inusual.
  • Paginación: navegación automática para registros extensos.
{# ── 5. Export CSV ───────────────────────────────────────────── #}

5 · Export CSV

El botón "Exportar CSV" descarga todos los registros que cumplan los filtros activos en ese momento. El archivo incluye todos los campos del evento de auditoría (actor_email, action, resource_type, resource_name, severity, status, detail, timestamp).

Casos de uso habituales:

  • Auditorías externas y revisiones de cumplimiento normativo (ISO 27001, GDPR, etc.).
  • Análisis offline en hojas de cálculo o herramientas SIEM.
  • Archivo periódico para gestionar el crecimiento del log.
{# ── 6. Retención ────────────────────────────────────────────── #}

6 · Retención

El log de auditoría no tiene límite de retención por defecto — crece indefinidamente en la base de datos PostgreSQL. En instalaciones de larga duración con alta actividad, esto puede representar un volumen de datos considerable.

Recomendaciones para gestionar el tamaño:

  • Exportar y archivar el CSV periódicamente (mensual o trimestral) y, si es necesario, purgar los registros más antiguos directamente en la base de datos.
  • El módulo de backup incluye el dump completo de la base de datos, por lo que los backups también capturan el log de auditoría.
El syslog forwarder (Ajustes → Syslog) puede reenviar en tiempo real las entradas del audit log a un servidor syslog externo (UDP/TCP, RFC5424). Esto permite retención externa ilimitada y facilita la integración con sistemas SIEM sin necesidad de exportar CSV manualmente.
